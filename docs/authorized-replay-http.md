# Authorized realtime HTTP

Six explicitly registered POST routes add `/realtime/snapshot`, `/realtime/replay` and `/realtime/stream` under the existing agent `/api/support/projects/{project}` and customer `/api/widget/projects/{project}` prefixes. Set `SUPPORT_REALTIME_HTTP_ENABLED=false` to withhold this bundle independently. The additive schema remains safe to retain; unused enrollments expire. No browser subscription or UI behavior is changed by this slice.

Agent requests use the native token cookie or hashed durable browser-session cookie, the native CSRF header/cookie pair, and the exact configured `config.app.url` Origin. Bearers, project keys and impersonation/identity overrides do not authorize these routes. Each checkpoint freshly validates native token ownership, revocation and password version, or resolves the current durable session, followed by current project/workspace and active membership checks. Neither Host nor forwarding headers configure authority.

Customer requests use only an opaque bearer session and an exact current project Origin allowlist match. Session and contact lookups join workspace, project and contact; contact existence and session expiry/revocation are current facts. Browser consumers must use credentials omitted. Cookies never substitute for a customer session, and credentials/cursors are refused in query strings. The current allowlist also controls response CORS. Authorization runs before/after finite reads, inside enrollment/renewal transactions, before commit and before releasing responses. Native stream subscription readiness, events and 15-second heartbeats recheck authority. A refusal closes the stream; bytes already written before the last check cannot be retracted.

Bodies are streamed through native `readJsonBody` with an 8 KiB actual-byte limit, fatal UTF-8 decoding and duplicate-key rejection. Native router body parsing is explicitly disabled for these routes so unbounded pre-parsing cannot bypass that limit. Snapshot accepts only optional canonical `conversationId`; replay and stream accept only `checkpoint: {incarnation, seq}` from a successful realtime snapshot. No channel, workspace or contact is selected by clients.

Snapshots serialize with mutations on the guarded workspace transaction and channel checkpoint lock. They return `{snapshot: {conversations, nextCursor, detail?}, mode, checkpoint, pollAfterMs: 30000}`. A bounded current-view projection and its channel head describe the same transactional instant. Customer projections and history cursors preserve the existing public activity semantics and 500-message default. Whole-row UTF-8 budgets are 128 KiB summaries, 256 KiB transcript, 64 KiB attachments and 512 KiB for the exact final envelope. Oversized rows fail boundedly. Older-page cursors name the last emitted row and never move the realtime checkpoint.

Only authorized snapshots enroll or reincarnate channels. A model-generated singleton named operator lock serializes admission and total persisted counts; limits are 1536 channels/project, 2048/workspace and 3072/operator, including expired rows awaiting cleanup. Lock order is operator, then deterministically ordered workspaces/channels. Ordinary mutations and finite replay/renewal take workspace then channel and cannot acquire the operator lock afterward. Cleanup reserves 127 background slots plus at most one requested expired incarnation, so it deletes at most 128 channels per snapshot. Native transaction ownership guards reject parent work during an active child savepoint and escaped closed callbacks. SQL always uses the guarded native database facade.

Capacity returns a successful bounded `snapshot-only` response with null checkpoint and no count disclosure. Existing live enrollments can renew at capacity; messaging does not depend on admission. Leases last 120 seconds and renew at most once every 30 seconds after current authorization. Expired replay/stream requests require a new snapshot. A new snapshot can delete expired event/channel state and receive a fresh native cryptographic incarnation. An old stream cannot renew that successor. Closing a tab or revoking one credential retains a shared enrollment until its lease expires.

Finite replay delegates to native `createDurableReplayResponse` and the existing SQL adapter, after first selecting a live scoped enrollment under the workspace lock. This guard is essential: native replay/prune can otherwise create an absent channel. The fixed retained policy remains 100 changed/null events, five minutes and 32 KiB replay pages. Only returned cursors advance progress. Missing/expired enrollment, retention, incarnation mismatch and cursor ahead return 409 with null cursor and snapshot required. Unexplained storage gaps return bounded 503 with null cursor and recovery required. Neither error skips omitted rows.

Streams use the native singleton broadcast hub, broadcast Response and existing support invalidation bus. The support bus retains explicit 4096-channel and 4096-subscription limits. Each browser tab is a subscription. Native pending limit 64, authorization failures, bus closure, abort and backpressure release the native subscription/hook/timer; after headers they close the stream rather than inventing an HTTP status or error event. Initial bus refusal is 503. Connected comments, heartbeats and changed/null or invalidated/null hints carry no durable checkpoint. Customer internal notes, assignment, read cursors and private files cannot advance customer durable state or hints; agent project channels are separate.

The later browser ticket must perform finite replay at least every 30 seconds and on reconnect/resume/hints, including while the subscriber appears healthy. This recovers producer-only Redis publication loss. Periodic full-state reconciliation remains necessary for public status/delivery/attachment fields outside the current producer allowlist. An empty replay is not proof that those fields are unchanged. This slice makes no general availability claim.

Qualification uses native routed registration/login/cookies/CSRF, generated SQLite/PostgreSQL and real Redis with an independent producer process. Missing PostgreSQL/Redis fails the full qualification matrix instead of skipping. The focused local filter is `bun test tests/feature/realtime-http.test.ts -t 'local.*sqlite'`. The isolated load fixture uses 16 setup workers and a 2048-request client pool to retain 1000 distinct enrolled messenger subscriptions plus an agent; it closes all readers/abort controllers in a finally block. This is bounded qualification load, not a production throughput benchmark. See `customer-projection.md` and `durable-realtime-persistence.md` for the existing privacy, UTC, pagination, rollback, worker-drain and producer-loss contracts retained underneath these routes.
